# Read-only KB MCP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Package a read-only Markdown KB MCP server reusable across independently configured KB instances.

**Architecture:** Build an immutable, validated publication registry from a configured Markdown index. Expose the registry through MCP resources and bounded list/search/read tools; package it as a self-contained toolkit with an inactive default server entry.

**Tech Stack:** Python 3.10+, uv/PEP 723, pinned `mcp==2.2.0`, safe YAML parsing with pinned PyYAML, existing TypeScript/Bun installer tests.

**Spec:** `docs/superpowers/specs/2026-10-29-kb-mcp-design.md`

**Review status:** approved with targeted revisions. The publication grammar,
budgets, filesystem walk, URI gate, support floor, and authorization conditions
below are required acceptance gates, not discretionary implementation details.

## Global Constraints

- Independent instance configuration: absolute root, URI prefix, metadata key, relative index path, navigation heading.
- Only valid index-allowlisted Markdown records; no approval-history verification.
- Default 20/max 100 results, 256-character nonempty search input, 512-character snippets, 1 MiB per record, 10,000 records, 64 MiB total snapshot.
- No writes, network fetching, execution, automatic link following, or live configuration edits.
- Reject traversal, symlinks, special files, duplicate identifiers/targets, malformed indexed records, and out-of-root targets.
- Snapshot bytes and SHA-256 hashes are fixed until restart; source changes during loading fail closed when detected by consistency checks.
- Do not copy private records or absolute user source paths into committed fixtures.
- Linux only; self-contained manifest-declared installed files, no source-relative runtime dependencies.
- Actual OpenCode checks require stable >=2.2.1 admitted by the shared numeric version runner; retain the actual measured version and sandbox isolation.
- The design's **Narrow publication grammar** and **Input and output budgets** are normative: exact single level-two heading/table, reject percent-encoded destinations (never decode), reject lexical path aliases, and reject duplicate target component tuples or device/inode identities.
- Config <=64 KiB; index/record <=1 MiB; line/frontmatter <=16 KiB; YAML <=1024 nodes/depth 8 with no aliases/anchors/explicit tags/merge keys/duplicates; metadata scalar <=4096 bytes, URI <=1024, title <=512, type <=128, relative path <=1024. The 64 MiB snapshot includes the index once, even when not published.
- Complete serialized list/search/resource-list responses <=256 KiB; reads <=16 MiB; errors <=1 KiB; cursors <=128 ASCII characters. Pagination must stop before exceeding byte budgets, including envelopes and duplicate result representations.
- Bound incoming stdio frames to 64 KiB and nesting to eight before parsing. IDs are signed 64-bit integers or <=128-byte strings; invalid/oversized ingress is never echoed. Configuration strings/nesting follow the explicit design caps.
- Full KB suite must pass on Python 3.10 and 3.13, or revise the support claim before shipping. uv provisioning is distinct from the server's prohibition on KB/network content fetching.

## Review Focus

- URI spelling and unusual authority/path forms: exact registry matching must not normalize distinct identifiers.
- Percent-encoded Markdown destinations and fenced/table-like text: only the configured navigation table authorizes files.
- FIFO/device paths and filesystem replacement races: loading must not block or follow an attacker-swapped link.
- Configuration and parser errors containing host paths: client errors and startup diagnostics must not disclose source paths.
- Installed launch after source removal: runtime and example configuration must not rely on the checkout.
