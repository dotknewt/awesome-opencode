### Exact OpenCode v2.0.30 source inspection: permission and runner limits

The following claims are **source-inspected** against the released [`v2.0.30` source tree](https://github.com/anomalyco/opencode/tree/v2.0.30), accessed through its raw source files on 2026-10-21. This source evidence sharpens the earlier documentation-level unknowns for the proposed preset-only configuration; it is not a runtime experiment and does not generalize to every possible OpenCode extension.

- [`packages/core/src/permission.ts:87-96`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/core/src/permission.ts#L87-L96) evaluates configured permission rules by matching action and resource and choosing the last matching rule (defaulting to `ask` when none match). [`:158-167`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/core/src/permission.ts#L158-L167) loads configured rules and evaluates requested resources. Normal permission allow evaluation contains no per-call budget or invocation counter. The source also has permission plugin hooks that can affect a permission result; such an extension is outside the approved preset-only scope and is not evidence of an available approved implementation.
- [`packages/core/src/tool.ts:231-244`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/core/src/tool.ts#L231-L244) filters available tools using permission rules, then separates direct tools (`codemode === false`) from Code Mode tools; Code Mode availability is separately determined from the `execute` permission. [`:292-296`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/core/src/tool.ts#L292-L296) implements `whollyDisabled` using the last matching action rule and checks for resource `*` with effect `deny`. This is availability filtering, not a quota on repeated invocation of an allowed send tool.
- [`packages/core/src/session/runner/llm.ts:226-244`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/core/src/session/runner/llm.ts#L226-L244) compares model-step count with the agent `steps` limit and sets `toolChoice: "none"` when the threshold is reached. This limits model steps/tool selection at that threshold; it does not limit the number of send invocations within an allowed model step.
- [`packages/core/src/session/runner/step.ts:88-111`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/core/src/session/runner/step.ts#L88-L111) executes a local tool for each provider `tool-call` event. Multiple calls create separate tool fibers and are tracked/awaited. [`:186-200`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/core/src/session/runner/step.ts#L186-L200) gates provider retry on `!recorded.outputStarted`; this is retry behavior, not a one-send guard or post-send model-fallback policy.
- [`packages/core/src/session/runner/retry.ts:64-93`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/core/src/session/runner/retry.ts#L64-L93) schedules retry attempts for the supplied model/session retry path. It does not select the approved fallback model. [`packages/schema/src/config/agent.ts:8-20`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/schema/src/config/agent.ts#L8-L20) defines optional agent `model` selection and `steps`; it contains no preset-native send quota or pre-send-only fallback control.

**Conclusion for the originally proposed hard-native-enforcement boundary (superseded):** inspected native permission and `steps` mechanisms do not enforce one `messages_send` invocation per notification; the runner can execute multiple provider tool-call events, including calls to the same allowed action. This source-backed finding is why the original hard guarantee was not supportable through preset permissions/steps alone. The user has since explicitly accepted instruction-level best effort for one-send/no-retry, so this finding is no longer a shipment prerequisite under the selected lightweight scope. It remains a factual limitation and must not be represented as native enforcement. This does not generalize to every possible extension. No inspected preset-native mechanism performs the desired parent-controlled fallback transition; failure observability and fallback handling remain unresolved. No runtime experiment was performed.

### OpenCode documentation facts and limits

- **Documented:** [Agents — Model](https://opencode.ai/v2/docs/agents/#model) says a subagent uses its configured model, or inherits the parent session model if none is configured. It does not document automatic switching to a fallback model after a pre-send failure. Agent `steps` ([Agents — Steps](https://opencode.ai/v2/docs/agents/#steps)) limits model steps/turns and removes tools on the final step; this is not a per-tool invocation quota and cannot establish one send maximum.
- **Documented:** [MCP servers — Names and Permissions](https://opencode.ai/v2/docs/mcp-servers/#permissions) says MCP tool names are normalized as `<server>_<tool>`, Code Mode is the default, and `codemode: false` exposes tools directly. A deny-all plus narrow normalized action allow is a candidate permission configuration, not a verified isolation result.
- **Documented:** [Tools — Execute and Extensions](https://opencode.ai/v2/docs/tools/#execute) says `execute` runs Code Mode and can call tools available through its namespace; denying `execute` removes Code Mode and tools reachable only through it, while nested tools still enforce their permissions. [Tools — Extensions](https://opencode.ai/v2/docs/tools/#extensions) distinguishes direct MCP tool exposure with `codemode: false`. Whether the candidate permission rules isolate the Hermes send action under both paths remains unmeasured.
- **Source-inspected, v2.0.30:** [`packages/protocol/src/groups/agent.ts`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/protocol/src/groups/agent.ts) defines `GET /api/agent` list/get routes with a `LocationQuery`; the repository's existing [`scripts/check-opencode-config-matrix.mjs:415-418`](../../../scripts/check-opencode-config-matrix.mjs) demonstrates disposable skill discovery via `GET /api/skill` and a location query. Exact `LocationQuery` query parameter encoding for a project directory has not been source-confirmed here; do not copy a guessed `location[directory]` query.
- **Source-inspected, v2.0.30:** [`packages/protocol/src/groups/session.ts`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/protocol/src/groups/session.ts) defines session creation with optional `agent` and `model`, and a prompt route spreading `PromptInput.Prompt.fields`. [`packages/schema/src/prompt-input.ts`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/schema/src/prompt-input.ts) defines prompt `text: string` (plus optional files/agents/skills), not a `parts` field. Thus the candidate `POST /api/session` agent/model fields and text prompt are source-backed; no complete request/response transaction has yet been tested.
- **Source-inspected, v2.0.30:** [`packages/ai/src/providers/openai-compatible.ts`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/ai/src/providers/openai-compatible.ts) configures an OpenAI-compatible route with `baseURL` and optional API key. [`packages/schema/src/config/provider.ts`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/schema/src/config/provider.ts) defines provider model records, headers/body overlays, and extensible settings; it does not alone establish the exact OpenCode config entry needed to register a local fake provider. The provider source excerpt does not establish tool-call parsing/round-trip support. Exact provider registration/configuration, tool-call support, and any credential-free local setup remain source-discovery prerequisites.
- **Source-inspected, build command candidate:** upstream [`packages/cli/package.json`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/cli/package.json) defines `build` as `bun run script/build.ts`. [`packages/cli/script/build.ts:27-31,57-72`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/cli/script/build.ts#L27-L31) recognizes `--single`, `--skip-web-ui`, `--target`, `--outdir`, and `--skip-install`; target selection/output handling is in [`:57-72,160-190`](https://github.com/anomalyco/opencode/blob/v2.0.30/packages/cli/script/build.ts#L57-L72). Target names are `opencode-linux-x64` (not `linux-x64`); custom outdir output is `<outdir>/cli-linux-x64/bin/opencode`. Without `--skip-install`, build script invokes `bun install`; output directory is recursively removed first. Dependency install/build can use network and package lifecycle hooks. No build was run.

Do not claim no binaries exist; no usable official binary/checksum was verified from that page view.

The user-selected lightweight preset accepts this single-send/no-retry limitation as model-compliance risk; it is superseded as a hard native-enforcement gate, not contradicted or solved.
